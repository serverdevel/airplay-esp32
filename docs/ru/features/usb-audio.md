# USB аудио (UAC)

Платы с портом OTG USB могут отображаться на подключенном компьютере как **стерео USB.
динамик**. Аудио, отправленное хостом, воспроизводится через тот же выходной путь, который использует AirPlay,
DSP ЦАП, эквалайзер и регулятор громкости.

!!! warning "Требуется USB OTG и порт роли устройства"

    Только ESP32-S2, S3 и P4 имеют периферийное устройство USB OTG. Контакты D+/D- также должны быть
    маршрутизируется к разъему, подключенному к роли устройства (раскрывающиеся списки CC). Оригинальный ESP32 не может
    вообще делай это.

Плата представляет собой составное устройство: динамик USB Audio Class плюс HID.
интерфейс потребительского управления, который отправляет медиа-ключи обратно на хост.

<a id="how-it-works"></a>
## Как это работает

- Аудио AirPlay и USB являются **взаимоисключающими во время выполнения**, как и
  [Bluetooth](bluetooth.md)
- AirPlay приостанавливается, как только хост начинает потоковую передачу.
- Выходные данные возвращаются после того, как хост-поток простаивает в течение некоторого времени.
  `CONFIG_USB_AUDIO_SINK_IDLE_MS`, 2000 мс по умолчанию
- Громкость хоста и отключение звука применяются к ЦАП, поэтому работает собственный ползунок громкости компьютера.
- [Аппаратные кнопки](buttons.md) отправляют на хост воспроизведение/паузу, пропуск трека, громкость и отключение звука.
  через HID, поскольку сам UAC не осуществляет никакого контроля за транспортировкой

<a id="sample-rate"></a>
## Частота дискретизации

Звук USB работает на частоте **48 кГц**. `CONFIG_UAC_SAMPLE_RATE` должно быть равно
`CONFIG_OUTPUT_SAMPLE_RATE_HZ`, потому что по этому пути и дескриптору ничего не пересчитывается
рекламирует единую фиксированную ставку.

!!! danger "44100 Гц не работает"

    `usb_device_uac` получает скорость опорожнения FIFO из `sample_rate / 1000`, целого числа.
    дивизия. На 44100 это усекает 44,1 кадра в миллисекунду до 44. Обратная связь
    конечная точка использует `AUDIO_FEEDBACK_METHOD_FIFO_COUNT`, так что FIFO является управляющей переменной.
    и хост устанавливает скорость 44000 кадров/с, в то время как I2S потребляет 44100. В результате дефицит
    примерно 100 кадров в секунду медленно истощает буфер, а затем дает сбой
    непрерывно. 48000 делится ровно на кадры по 1 мс.

По этой причине платы TAS58xx по умолчанию используют частоту 48 кГц, а также потому, что коэффициенты эквалайзера драйвера
рассчитаны для 48 кГц. Поток AirPlay с частотой 44,1 кГц подвергается повторной выборке на выходе.

<a id="build-environments"></a>
## Среды сборки

| Среда сборки | Совет |
| --- | --- |
| `esp32s3-uac` | ESP32-S3 + PCM5102A |
| `esparagus-audio-brick-dual-uac` | [Esparagus Audio Brick Dual](../boards/esparagus-audio-brick-dual-dac.md) |

Звук USB включается путем наложения `config/sdkconfig.defaults.uac` на настройки платы по умолчанию. Чтобы
добавьте его на [пользовательскую плату](../boards/custom.md), поместите этот файл **последним** в свой
`SDKCONFIG_DEFAULTS`, чтобы он мог переопределить частоту дискретизации.

<a id="device-name"></a>
## Имя устройства

`CONFIG_USB_AUDIO_SINK_PRODUCT` устанавливает имя, отображаемое хостом. Он используется как для
строку продукта и аудиоинтерфейс, который показывает диспетчер устройств Windows.
составная функция.

!!! tip "Windows кэширует имя"

    Windows хранит строки дескрипторов для каждого VID/PID/версии, поэтому после изменения имени
    может продолжать показывать старый. Вставьте `bcdDevice` в `main/usb/usb_descriptors.c`, чтобы заставить
    перечитывание.

<a id="caveats"></a>
## Ограничения

- **macOS** требуется `CONFIG_UAC_SUPPORT_MACOS=y`. Один дескриптор не может удовлетворить macOS и
  Windows/Linux одновременно, так что это выбор во время сборки.
- **Нет консоли USB.** TinyUSB претендует на PHY USB, поэтому USB-Serial-JTAG не может также выступать в качестве
  консоль. Журналы остаются на UART0, и вам необходимо удерживать BOOT во время сброса, чтобы перепрошить через USB.
  [Обновления OTA](../reference/ota.md) полностью устраняют проблему.
