# Настройка AirPlay

Расширенные параметры синхронизации и метаданных находятся в разделе **AirPlay Receiver → AirPlay Protocol** в
`menuconfig`. Значения по умолчанию подходят для большинства настроек — меняйте их только в том случае, если вы слышите пропадание или
хотите контролировать, какие метаданные будут получены.

<a id="cover-art"></a>
## Обложка

Обложка альбома **отключена по умолчанию**. Большинство приемников не имеют экрана или имеют лишь небольшой
OLED, а также перетаскивание изображения через соединение RTSP может привести к остановке аудиоконвейера и вызвать
выпадения — особенно в небуферизованных потоках AirPlay1/realtime.

Если этот параметр отключен, приемник удаляет тип изображения `1` из объявленной txt-записи `md`, поэтому
отправители вообще не передают обложки и игнорируют все, что приходит. Название трека,
Метаданные исполнителя, альбома и прогресса принимаются всегда.

Чтобы включить его, например, если у вас [TFT-дисплей](tft-display.md):

```bash
idf.py menuconfig
# AirPlay Receiver → AirPlay Protocol
# Enable "Enable cover-art / artwork reception"
```

Или в настройках sdkconfig по умолчанию:

```ini
CONFIG_ENABLE_AIRPLAY_ARTWORK=y
```

<a id="forcing-airplay-v1"></a>
## Форсирование AirPlay v1

Классический AirPlay v1 заставляет приемник рекламировать себя как обычный RAOP-приемник. Есть
две причины сделать это:

- **Аппаратные кнопки.** iOS отправляет заголовки DACP только в режиме v1, поэтому именно это и делает
  [аппаратные кнопки](buttons.md#read-this-first-the-airplay-v1-requirement) работают.
- **Apple Music для Windows.** Это отправитель только для RAOP, который не принимает любое устройство,
  рекламирует сервис `_airplay._tcp`, сообщая, что устройство «несовместимо
  с этой версией AMPLibraryAgent". Устройство по-прежнему отображается в средстве выбора, и оно
  по-прежнему открывает соединение RTSP — оно отправляет `OPTIONS` с `Apple-Challenge`, а затем
  уходит.

Этот режим находится в NVS, поэтому пересборка не требуется. Откройте веб-интерфейс и выберите
**Настройки устройства → Режим AirPlay**, затем перезагрузите устройство. Записи mDNS и RTSP.
Оба порта прослушивания создаются при запуске, поэтому изменения вступят в силу только при следующей загрузке.

В режиме v1 приемник отображает классическую рекламу RAOP: нет `_airplay._tcp`.
сервис, TXT-запись `_raop._tcp` в стиле shairport-sync, `Server: AirTunes/105.1` на RTSP
ответы и RTSP на порту 5000 вместо 7000.

Это стоит вам AirPlay 2 функции: сопряжение с HomeKit, зашифрованная передача и синхронизация с несколькими комнатами.

Не существует настройки, которая бы устраивала обоих отправителей. Решающим фактором для Apple Music является
наличие только `_airplay._tcp` — ресивера, издающего полностью классический `_raop._tcp`
Запись TXT на порту 5000 по-прежнему отклоняется, пока эта служба работает, и начинает работать
момент, когда он будет снят. iOS требуется одна и та же служба для согласования AirPlay 2, а устройство
публикует одну рекламу, так что режим настоящий «или/или».
