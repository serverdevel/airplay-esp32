# Esparagus Audio Brick Dual

!!! warning "Унаследованный непроверенный профиль"

    Эта страница описывает исходный код, унаследованный от основного проекта. Данный
    форк не тестирует эту плату, не публикует для неё готовый образ и не предоставляет
    официальную поддержку. Самостоятельная сборка и проверка выполняются на ваш риск.

**Audio Brick Dual** — это **ESP32-S3** [Esparagus Audio Brick](esparagus-audio-brick.md)
несущий **два** усилителя класса D на одной шине I2S. Как и каждый кирпичик, каждый представляет собой либо
TAS5825M или TAS5805M, и драйвер определяет, какой из них при запуске.

Два усилителя создают настоящий активный кроссовер: сателлиты на одном чипе, 
мостовой сабвуфер или вторая стереопара с другой стороны, разделенная на DSP 
а не пассивной сетью.

<a id="features"></a>
## Функции

- Два усилителя, обнаруженные по адресам I2C **0x4C** и **0x4D**.
— 15 биквадратных секций на выход, на усилитель — всего 60 по четырем выходам
- Второй усилитель, подключенный как мостовой моносабвуфер или как вторая стереопара,
  переключается через веб-интерфейс
- [W5500 SPI Ethernet](../features/ethernet.md) с автоматическим аварийным переключением WiFi
- Опционально [аудио USB](../features/usb-audio.md) — родной для S3 USB обеспечивает плату с двумя ЦАП. 
  динамик USB, а также динамик AirPlay
- I2C и SPI доступны для внешних дисплеев, датчиков и расширителей GPIO.
- 8 МБ флэш-памяти, восьмеричная PSRAM
- Нет Bluetooth: для A2DP требуется Bluetooth Classic, которого нет в ESP32-S3.

<a id="flashing"></a>
## Прошивка

```bash
# AirPlay + Ethernet
pio run -e esparagus-audio-brick-dual-dac -t upload
pio run -e esparagus-audio-brick-dual-dac -t uploadfs

# The same board, also enumerating as a USB speaker
pio run -e esparagus-audio-brick-dual-uac -t upload
pio run -e esparagus-audio-brick-dual-uac -t uploadfs
```

Под ESP-IDF:

```bash
idf.py set-target esp32s3
idf.py -DSDKCONFIG_DEFAULTS="config/sdkconfig.defaults;config/sdkconfig.defaults.esparagus-audio-brick-dual-dac" build
idf.py -p /dev/ttyUSB0 flash
```

Этот форк не публикует готовый образ ни для одного из вариантов.

<a id="default-gpio-assignments"></a>
## Назначения GPIO по умолчанию

Плата с двумя ЦАП использует те же контакты I2S, I2C, SPI и дисплея, что и версия S3, и отличается тем, что
делает это с двумя контактами, которые плата с одним ЦАП использует для FAULTZ и PWDN.

| Функция | GPIO | Заметки |
| --- | :-: | --- |
| I2S BCK | 14 | Битовые часы |
| I2S WS | 15 | Выбор слова (LRCLK) |
| I2S ДЕЛАТЬ | 16 | Последовательные аудиоданные, оба усилителя |
| I2C ПДД | 8 | Порт управления, оба усилителя |
| I2C СКЛ | 9 | Порт управления, оба усилителя |
| Включение ЦАП 1 | 18 | PDN для усилителя по адресу 0x4C |
| Включить ЦАП 2 | 17 | ПДН для усилителя по адресу 0x4D |
| Светодиод состояния | 21 | Адресный RGB |
| СПИ СКЛК | 12 | Совместно используется Ethernet и дисплей |
| СПИ МОСИ | 11 | Совместно используется Ethernet и дисплей |
| СПИ МИСО | 13 | Только Ethernet |
| Ethernet CS | 10 | W5500 |
| Ethernet ИНТ | 6 | W5500 |
| Ethernet РСТ | 5 | W5500 |
| Показать CS | 47 | SH1106 OLED |
| Дисплей постоянного тока | 38 | SH1106 OLED |
| Показать РСТ | 48 | SH1106 OLED |

!!! note "Нет линии неисправности"

    GPIO 18 и 17 — это два включения ЦАП, поэтому ни один из выводов FAULTZ усилителя не используется.
    достигает MCU (`CONFIG_SPKFAULT_GPIO=-1`). Драйвер опрашивает неисправности обеих частей
    Вместо этого регистрируется каждые две секунды, что фиксирует перегрузку по току и перегрев.
    завершение работы немного позже, чем прерывание, но сообщает те же детали.

<a id="amplifier-roles"></a>
## Роли усилителя

Роли следуют порядку обнаружения, который соответствует адресу I2C:

| Индекс | Адрес | Роль |
| --- | --- | --- |
| 0 | 0x4C | Стереосателлиты, всегда пара BTL |
| 1 | 0x4D | Второй усилитель — мостовое моно или вторая стереопара |

Оба получают один и тот же поток I2S; то, что каждый из них делает, определяется его собственным входом DSP
микшер, поэтому никакая внешняя проводка не влияет на маршрутизацию.

<a id="second-amplifier-wiring"></a>
### Проводка второго усилителя

**Второй усилитель** на главной веб-странице позволяет выбрать один из двух:

- **Мостовое моно (PBTL)** — OUT_A и OUT_B подключены параллельно к одному драйверу, для
  сабвуфер. По умолчанию на усилитель подается питание `(L+R)/2`, поскольку одна звуковая катушка не имеет
  стерео для воспроизведения.
- **Стерео (BTL)** — два отдельных динамика, как на первом усилителе.

!!! danger "Переподключение перед перезапуском"

    PBTL — это настройка порта управления, записанная, когда деталь все еще находится в режиме HiZ, поэтому изменение
    вступает в силу при следующей загрузке, а не сразу. **Согласуйте проводку динамика с
    перед перезапуском.** Оставьте OUT_A и OUT_B замкнутыми вместе, пока деталь
    возникает, когда стерео пара BTL направляет два выхода друг против друга и может
    повредить усилитель и его выходные фильтры. Веб-интерфейс попросит вас подтвердить
    по этой причине.

Настройка сохраняется в NVS и считывается до инициализации ЦАП, поскольку PBTL
должно быть установлено до того, как выходной каскад начнет управлять нагрузкой.

<a id="crossovers-and-eq"></a>
## Кроссоверы и эквалайзер

На странице [Эквалайзер](esparagus-audio-brick.md#equaliser) оба усилителя рассматриваются как один.
система. **Кроссовер** предлагает макеты, которые возможны на плате с двумя ЦАП — твитеры на одном
усилитель и НЧ с другой, или сателлиты плюс саб — и пишет
фильтры, группирование и входная маршрутизация на каждый выход, к которому прикасается разделение. Применять всегда
соединяет оба усилителя вместе, поэтому кроссовер, охватывающий пару, никогда не сможет работать
половинки.

Выбор каждого выходного канала исчезает с главной страницы, как только два усилителя подключены.
нашел: с кроссовером в DSP маршрутизация уже определена, поэтому выбираем ее еще раз
за выход ничего бы не значило.

<a id="ppc3-dumps"></a>
## Дампы PPC3

Используются ЦАП TAS5825M, поэтому [полные настройки PPC3](esparagus-audio-brick.md#full-ppc3-tuning)
apply — по одному файлу на усилитель, индексируемому по порядку обнаружения:

| Файл | Применяется к |
| --- | --- |
| `/spiffs/hf/tas5825m_fw0-44100.bin` | усилитель на 0x4C, на частоте 44,1 кГц |
| `/spiffs/hf/tas5825m_fw1-44100.bin` | усилитель на 0x4D, на 44,1 кГц |
| `/spiffs/hf/tas5825m_fw0-48000.bin` | усилитель на 0x4C, 48 кГц |
| `/spiffs/hf/tas5825m_fw1-48000.bin` | усилитель на 0x4D, на 48 кГц |

Журнал PPC3, который управляет обоими усилителями, содержит записи для каждого, поэтому преобразуйте его дважды:
ковыряем устройство с `--dev 98` или `--dev 9a`:

```bash
python3 components/dac_tas58xx/ppc3_convert.py both_amps.cfg --dev 98 -o tas5825m_fw0-48000.bin
python3 components/dac_tas58xx/ppc3_convert.py both_amps.cfg --dev 9a -o tas5825m_fw1-48000.bin
```

Неиндексированный `tas5825m_fw-<rate>.bin` обозначает только первый усилитель, так что на ред.
D Во избежание путаницы стоит использовать индексированные имена.

<a id="usb-audio"></a>
## USB аудио

`esparagus-audio-brick-dual-uac` — та же плата с
[Аудио USB](../features/usb-audio.md) наложено. Хост видит стереодинамик USB
питание того же DSP, кроссовера и регулятора громкости, которые использует AirPlay, а AirPlay приостановлен
пока хост ведет потоковую передачу.

Звук USB работает на частоте **48 кГц** — см. [предупреждение о частоте дискретизации](../features/usb-audio.md#sample-rate)
почему на этом пути не работает 44,1 кГц. Поток AirPlay с частотой 44,1 кГц передискретизируется на
выход, поэтому дамп PPC3 с частотой 48 кГц — это тот, который имеет значение в сборке UAC.

TinyUSB претендует на PHY USB, поэтому USB-Serial-JTAG также не может быть консолью в этой сборке.
Журналы остаются на UART0, а для перепрошивки через USB требуется удержание BOOT во время сброса;
[Обновления OTA](../reference/ota.md) обходите это стороной.
